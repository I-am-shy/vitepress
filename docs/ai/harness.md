# Harness

## 什么是 Harness ？

Harness(马鞍，约束的器具) 是辅助 AI 模型执行任务的一系列架构、工具、方法等的总称。一切优化 AI 模型的“外力”都可以称为 Harness，例如，使用 Agentic Loop 架构和更优的提示词，提供 Terminal 并给予操作系统的权限。

> Harness 的目的是让 AI 模型能更精确的完成任务。

## Agent 工作区 

Agent 工作区（Agent Workspace）是 AI Agent 用于存储长期记忆、执行任务、读写文件以及调用外部工具的专属运行目录或集中化操作环境。

> [!NOTE] 说明
> 工作区的载体就是一个项目文件夹。

- 核心组成与功能主目录与上下文：它是 Agent 的“长期记忆”和主目录，保存了提示词文件、设定、技能、用户资料及历史产物。

- 规范与设定：通常包含定义 Agent 身份、行为准则或灵魂设定的核心配置文件（如 Markdown 格式的引导文件）。

- 工具与数据交互：在工作区中，Agent 可以被授权安全地连接外部数据库、API 或模型工具，在设定的权限边界内自主规划和执行多步骤任务。

## OpenClaw 的引导文件机制

OpenClaw 通过一组引导文件（bootstrap files）在每次会话开始时注入，从而把泛用型 agent "调教"成特定角色：

```md
AGENTS.md（操作规则）、SOUL.md（人格语气）、USER.md（用户身份）、IDENTITY.md（名称风格）、TOOLS.md（工具约定）、MEMORY.md + memory/YYYY-MM-DD.md（长期/每日记忆）、skills/（工作区专属技能）
```

| 维度 | 改哪里 |
| --- | --- |
| 角色与职责 | AGENTS.md § 角色（改几个字，agent 就从"前端工程师"变成"翻译专员"或任何角色） |
| 能力边界（做/不做） | AGENTS.md § 能力边界 |
| 人格、语气、语言 | SOUL.md |
| 自称、风格、表情 | IDENTITY.md |
| 工具使用习惯 | TOOLS.md（优先用什么、避免什么模式） |
| 长期记忆与领域知识 | MEMORY.md + memory/ |
| 专属能力扩展 | .dsh/skills/——这个比较"硬"：技能是真实加载进目录的，相当于给 agent 装新本事 |


这些文件主要是提示词层面的引导（TOOLS.md 明确"不控制工具可用性，仅提供指导"），硬隔离由独立的沙箱机制负责

> [!WARNING] 沙箱
> 沙箱 (sandbox) 是一个系统里的隔离环境，沙箱环境限制了权限只能读写环境内部的文件。

### 引导文件的生命周期

一组引导文件在 Agent 工具（claude code、codex、openclaw、deepseek harness等）里经历了以下阶段：

1. 开启一个新会话 Agent 工具会先读取工作区 AGENTS.md 的内容，加入到上下文中。（此文件是约定好的协议，一定会读取，其他文件是否默认读取看 Agent 工具的配置）
2. 根据 AGENTS.md 开启二段式引导。（Agent 工具会读取 AGENTS.md 里涉及的其他引导文件）

    ```md
    新会话：用户首条消息
      → 基线注入 AGENTS.md
      → 启动协议指令 agent read SOUL/USER/IDENTITY/TOOLS/MEMORY + 日志
      → 这些 read 是普通工具调用，结果直接进上下文（它们不是候选名，不触发注入）
      → 角色完全体，开始工作
    ```
3. SKILLS 是渐进式批漏，只有当需要使用时才会加入到上下文。

这些引导文件是 AGENT 的核心，它们以真实文件的形式持久化保存了 AGENT 的记忆、能力、职责。

**一句话版本**

引导文件就是几张纸，写着“这个 AI 是谁、该干什么、不该干什么”。AI 每次开新对话都会把之前的事忘个精光，但系统保证它一睁眼就能看到这几张纸。


**打个比方：AI 是个每天入职的新员工**

- AI（我） = 新员工。每天来上班，昨天的事全忘了，但干活本事还在
- 工作区文件夹 = 他的工位
- AGENTS.md = 《员工手册》——前台每天必发，不发不行。这是系统代码干的，不靠员工自觉
- 手册第一页写着：“上班先去抽屉里翻这几份文件”：
    - SOUL.md = 你的性格、怎么说话
    - USER.md = 老板是谁、有啥偏好
    - IDENTITY.md = 你叫什么名字
    - TOOLS.md = 用工具的规矩
    - MEMORY.md + memory/日记本 = 前几天的交接记录
- memory/ 文件夹 = 交接日记。每天下班写一篇，明天的新员工读了，记忆就接上了

**生命周期 = 新员工的一天，就 5 步**

1. 入职：新会话开始，AI 失忆上线
2. 发手册：系统自动把 AGENTS.md 塞到它眼前（100% 保证）
3. 翻抽屉：它按手册的嘱咐去读另外几张纸和昨天的日记（基本都听话）
4. 白天：你随时改纸。AI 下次一碰文件，系统发现纸变了，立刻把新版塞过去：“以这版为准”（也是自动的）
5. 下班：重要的事写进日记 → 明天回到第 1 步

---
> [!TIP] 最后一句大实话
>
> 纸只能嘱咐，不能上锁。AI 听话率很高，但没有手铐——真要防它干某件事（不许删文件、不许上网），得用系统层面的锁（换模式、沙箱、审批）。那不是纸能干的活。
